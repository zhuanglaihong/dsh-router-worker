# 实现计划：右键菜单里的「子对话」

> 本文只是**计划**，不包含代码改动。前两步（主题无关的子树 + 任意模式的父子关系）已经实现并在 `dsh-subagent-tree` 里可用了。

## 1. 现状：为什么现在只有「分叉会话」

截图里那个右键菜单是**宿主自己画的**，不是任何插件：

| 菜单项 | 谁的实现 | 语义 |
|---|---|---|
| 置顶会话 | 宿主 `sidebar.workspaces` | 把行钉到顶部 |
| 重命名 ⌥⌘G | 宿主 | 改 `displayTitle` |
| **分叉会话 ⌥⌘F** | 宿主 `uiWorkspace.forkSession` | 复制当前会话已完成的轮次前缀，**开一条独立的平级会话** |
| 复制 Session ID | 宿主 | 剪贴板 |
| 在 Finder 中显示 | 宿主 | 打开 `cwd` |
| 归档会话 ⇧⌘A | 宿主 | 归档 |

关键区别：

- **分叉 = 克隆**。新会话与源会话**没有持续关系**，源会话不知道它的存在，两边各自演进；它出现在列表里是**平级**的。
- **子对话 = 派生**。新会话**永远挂在源会话下面**，`origin: 'subagent'` + `parentId`，宿主把它当子代理会话对待（当前是隐藏、不出现在列表里，这正是本插件要补的那一块）。

所以「加一个子对话菜单项」不是加一个按钮，而是**加一条新的派生通道**：现在宿主只提供 `fork`，没有提供「以子代理身份开一条会话」的公开 API。

## 2. 三条可选路线

### 路线 A（推荐）：菜单项 + 一次性子代理任务书

**做法**：在右键菜单里加「子对话」；点击后弹一个**单行输入框**（要它做什么），插件把这句话作为任务书派给一个子代理，子代理会话的 `parentId` 自动就是当前会话。

```
右键「子对话」 → 输入框「把这份需求拆成三步并列出每步的验收标准」
                → 派发 → 列表里当前会话下立刻长出一行 #1
```

- **协调关系**：一次性委派。子代理只做这一件事，做完把结论作为一条消息回到主会话（DSH 原生 subagent 的行为），然后 `inactive`。
- **优点**：几乎不需要新机制，完全是 `subagent` 工具现有的语义；`parentId` 由宿主写入，本插件的树自动就能显示。
- **代价**：用户要写一句任务书；这不是「一条可以继续聊的对话」，做完就结束。
- **实现要点**：
  1. 菜单注入：宿主没有 `sidebar.workspaces.session.row.action` 之外的菜单插槽（那个是行尾 hover 按钮，不是右键菜单），所以仍然要 DOM 注入 —— 监听 `contextmenu`，找到右键的那一行 `[data-row-key^="session:"]`，在宿主菜单容器里插一项（锚点用 `role="menu"`）。
  2. 派发：客户端不能直接调工具，需要一条 Host Remote：`subagentTree.dispatch({ parentSessionId, brief })`，host 半调 `ctx.get('subagents').spawn(...)`（或复用 `tool-subagent` 的执行面）。
  3. 结果回流：子代理完成事件 → 往主会话注入一条消息（`sessions.prompt(..., 'queue')` 的等价物）。

### 路线 B：可续接的「侧边子对话」

**做法**：同上，但派出去的是一个 **continuable** 子代理（`mode: 'continuable'`），用户可以再次进入这条子对话继续追问，它还记得上下文。

- **协调关系**：半独立。主会话知道它在做什么（能收到报告），但不会替它改任务书；用户可以随时插手。
- **优点**：最贴近用户对「子对话」的直觉 —— 一个能一直聊下去的下属。
- **代价**：`continuable` 子代理的生命周期、上下文上限、多轮记忆都要宿主支持；`SidebarSubagentCatalogEntry.mode` 已经有 `'continuable'` 这个值，说明宿主有这类子代理，但**从客户端主动创建**一条 continuable 子会话的路径还需要在 host 半确认。
- **实现要点**：路线 A 的全部 + host 半确认 `spawn` 是否接受 `continuable`；打开子对话时用 `subagentchat` 资源地址（`mode=continuable`），本插件已经写好了这条打开路径。

### 路线 C（不推荐）：替换宿主的右键菜单

**做法**：把 `sidebar.workspaces` 整块换掉，自己画列表和菜单。

- **代价**：`replaceRisk: "shadows-shipped-ui"`，等于把宿主的会话列表整套重新实现一遍 —— 置顶 / 重命名 / 归档 / 拖拽 / 多选 / 键盘导航全要跟着做，宿主每次升级都可能崩。**不建议**。

## 3. 推荐路线与工作量

走 **A → B** 的渐进路线：

| 阶段 | 内容 | 预估 | 风险 |
|---|---|---|---|
| A1 | 右键菜单注入「子对话」项 + 单行输入框 | 半天 | 菜单容器锚点可能随宿主改版变化，需要降级（找不到就退回 `topic` 事件） |
| A2 | Host Remote `dispatch`：把任务书派成子代理 | 半天 | 需要在 host 半确认 `ctx.get('subagents')` 的 spawn 形状 |
| A3 | 结果回流到主会话 + 树上出现新行 | 2 小时 | 本插件已有渲染，`parentId` 一到就自动显示 |
| B1 | 改成 continuable，支持二次进入 | 1–2 天 | 宿主是否开放客户端侧创建 continuable 子会话，需先验证 |
| B2 | 子对话内追加指令的输入框（需要宿主 `subagentchat` 支持写入） | 视宿主能力 | 可能做不了，只能只读回放 |

**先做 A1**：它不改任何数据模型，只是把一条已经存在的通道（`subagent` 工具）搬到右键菜单里，失败了也不影响现有功能。

## 4. 与「分叉会话」的共存

两者不冲突，语义不同，菜单里并排放：

```
✂️ 分叉会话 ⌥⌘F      → 克隆一个平级会话，双方对等
💬 子对话             → 派一个下属，永远挂在当前会话下面
```

用户的心智模型：**分叉是「我自己再开一条线」，子对话是「我让别人去干一件事」**。

## 5. 需要你确认的三件事

1. **子对话要不要能继续聊**？只能做一次（路线 A，简单）还是能反复追问（路线 B，需要更多宿主能力）？
2. **子对话用什么模式跑**？继承主会话的模式（标准/Multitask），还是固定用某个轻量模式？
3. **结果怎么回到主会话**？自动插一条消息（会打断当前对话节奏），还是只在树里点亮 + 主会话的 `job_output` 里能查（更安静）？
